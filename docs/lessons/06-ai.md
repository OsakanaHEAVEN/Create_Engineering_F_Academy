# 画像と文字から説明が返るまで

[本編に戻る　4　データ型と契約](../course/meaning.md)

外部AIに送る前と返事が届いた後では、確かめることが違います。ここでは写真の中身が準備されてから、説明とタグをPythonで使える値にするまでを追います。

## 「何が写っているか」と「何に使うか」

紙にRC回路が描いてあるとき、説明は「抵抗とコンデンサの回路図」でよい。用途は復習か、後でAIに質問するためかで変わる。そこで付加は説明とタグを作り、別の分類処理が最新のカテゴリ一覧と照合する。分類名を変えても画像をもう一度送らずに済む。音声認識は聞き取り係、Visionは画像と聞き取りメモを読む記述係に相当する。両者は正解を保証する審査員ではなく、構文検証を通った説明にも事実誤認はありうる。

| 呼出し | 渡る形式 | 戻り値・副作用 |
|---|---|---|
| `transcribe_wav(Path(...))` | ローカルWAVのパス | faster-whisperのsegmentsから `s.text` を順につなぎstrip。初回はモデル取得が必要な場合がある |
| `GeminiVisionProvider(consent=...).annotate(path, transcript)` | 画像パス、例「復習用」 | 同意→キー→ファイル→SDKの順に検査。通ればJPEGを用意 |
| `_clean_jpeg` | ローカル画像 | EXIFの向きを反映しRGBで再符号化、メモリ上のJPEG形式の画像データを返す |
| `generate_content` | 指示と文字起こしを含むテキスト、JPEG形式の画像データを包んだPart | 画像1枚の要求。音声ファイル自体はこの呼出しに渡らない。生成呼出しのfinallyでclientを閉じる |
| `_parse_annotation` | `response.text`、既知の文字起こし、モデル名 | JSON検証後に `contracts.Annotation` を返す。ここではDBに書かない |

`_whisper_model` の `lru_cache(maxsize=2)` はモデルサイズをキーに実体を再利用する。「同じ写真の文字起こし結果をキャッシュする」という意味ではない。テストはモデル生成を置き換え、同サイズで2回呼んで生成が1回か検査する。[transcribe_wav](https://github.com/OsakanaHEAVEN/Create_Engineering_F/blob/e7dbd20b3e581878729673e2cd82ea60719336e4/src/imagebox/augmentation/audio.py#L38-L42) [tests/test_whisper_cache.py](https://github.com/OsakanaHEAVEN/Create_Engineering_F/blob/e7dbd20b3e581878729673e2cd82ea60719336e4/tests/test_whisper_cache.py) [GeminiVisionProvider.annotate](https://github.com/OsakanaHEAVEN/Create_Engineering_F/blob/e7dbd20b3e581878729673e2cd82ea60719336e4/src/imagebox/augmentation/service.py#L55-L97)

### JSONは文字列から検証済みの値へ

[実験ファイル　response.py](../labs/response.py)

```python
"""ネット送信を行わず、実際の応答検証関数だけを呼ぶ。"""
from imagebox.augmentation.service import _parse_annotation
from imagebox.core.contracts import ValidationError

for payload in ['{"caption":"  RC板書  ","tags":[" 回路 "]}', '[]', '{"caption":"x","tags":[3]}']:
    try:
        a = _parse_annotation(payload, "復習用", "教材モデル")
    except ValidationError as error:
        print(type(error).__name__, str(error))
    else:
        print(a.caption, a.tags, a.transcript, a.prompt_version)
        assert a.tags == ["回路"]
```

1件目は `json.loads` で辞書になる。captionの両端を取り除いた長さが1〜1000、tagsが最大10要素のリストで各要素の長さが1〜50なら、整形した値と呼出側のtranscriptを組み合わせて戻す。2件目は有効なJSONでも配列なので失敗。3件目はtagsが配列でも要素が数値なので失敗。モデルへの出力スキーマ指定と、受信後にPythonで検査することは別の防衛線になる。[_parse_annotation](https://github.com/OsakanaHEAVEN/Create_Engineering_F/blob/e7dbd20b3e581878729673e2cd82ea60719336e4/src/imagebox/augmentation/service.py#L22-L45) [tests/test_gemini_provider.py](https://github.com/OsakanaHEAVEN/Create_Engineering_F/blob/e7dbd20b3e581878729673e2cd82ea60719336e4/tests/test_gemini_provider.py)

### 失敗はどこまで伝わるか

| 条件 | 現在の部品の動作 | 上位に必要な判断 |
|---|---|---|
| 同意なし・キー未設定 | `ProviderUnavailable` | 送信せず設定を待つ。予定ジョブを誤って完了にしない |
| パスなし | 前段の条件を満たせば `FileNotFoundError` | 写真・管理パスを点検 |
| 不正JSON | `ValidationError` | エラーを記録、元写真を保持 |
| 通信タイムアウト・429 | SDK例外をこの関数は分類・再試行しない | 契約の `RateLimited` 等への対応、上限付き再試行はワーカー側を含む今後の実装 |

### 同意なし、キーなし、画像なしを同時に入力すると何が先か。

同意の検査が先なので ProviderUnavailable。ファイル存在チェックにも画像送信にも進まない。例外の種類だけではキー不足との区別がつかない場合がある。

### 応答にcategory_idが余分に含まれていたら分類結果として保存されるか。

parserが読み取るのはcaptionとtags。戻るAnnotationにcategory_idフィールドはない。分類は別Providerが行う契約で、現行GUIからは自動起動しない。
